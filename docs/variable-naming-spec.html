Reference - Read before naming anything

Variable Naming Specification

Four collections, each answering one question. Slots appear in a fixed order, each slot draws from a closed list, and unused slots are dropped - never reordered. Learn the grammar once and you can name any token without asking.

This page is the rules, built to be looked up. It carries no justification on purpose - why each rule exists lives in naming-decisions.md. The full token inventory lives in token-architecture-v2.md.

01

How to read a token name

Token names are paths. Figma turns each slash into a folder, so the name is both an address and a sentence. Position carries meaning - the second segment is always the same kind of word.

Element Role State
Elementsurface / Roleprimary / Statehover

"The background of a primary action, while hovered."

Read it left to right and it narrows: what kind of thing -> what does it mean -> in what condition. That is the whole Interface grammar, and Interface is what components bind.

The one rule underneath all the others

Slots are positional, not labelled. Nothing in the name says "this part is the state" - you know it's the state because it's last. That is why order can never change and why words can't be borrowed between slots.

02

The four collections

Each answers a different question, and each may only reference the one above it. That chain is what lets one design system carry several brands and both themes without touching a component.

1 - Primitives141 - 1 mode: Value

What is the raw value?

Raw values with no opinion about use. A blue is just a blue. Never bind these to a design - they exist to be referenced.

color/blue/500 spacing/16 scale/12
2 - Semantics106 - 1 mode per brand

What is this brand's red?

Brand identity. Full ramps, so Interface can pick different steps for light and dark. Also carries shape and density, because a brand can be sharp or round, dense or airy. Knows nothing about light/dark.

primary/500 error/700 radius/xl
3 - Interface103 - 2 modes: Light / Dark

What does it look like right now?

Application roles. This is the only colour layer a component may bind. Theme resolves here. Knows nothing about which hue "error" is.

surface/primary/hover text/on-color border/error-subtle
4 - Breakpoint30 - 3 modes: Desktop / Tablet / Mobile

How big, at this screen size?

Geometry and type scale only - never colour. Set the mode on a top-level frame and everything below it reflows. Runs parallel to the chain, not inside it.

type/h1 grid/margin

Who may reference whom

FromMay alias toMust never alias to
PrimitivesNothing - raw values onlyAny other collection
SemanticsPrimitivesInterface, Breakpoint, another Semantics token
InterfaceSemanticsPrimitives, another Interface token
BreakpointPrimitivesSemantics, Interface
A componentInterface, BreakpointSemantics, Primitives
The rule that makes theming work

An Interface token that reaches past Semantics to a primitive cannot be re-branded, and a component that binds Semantics directly cannot be re-themed. Both look fine on the day they are made. Neither is recoverable without a migration.

03

The grammar

Each collection has its own slot sequence. Within a collection the order never varies. A slot is dropped when the token has only one possible value for it - the remaining slots keep their positions.

CollectionSlot sequenceExample
Primitivesfamily / stepcolor/blue/500, spacing/16
Semanticsgroup / stepprimary/500, radius/xl
Interfaceelement / role / statesurface/primary/hover
Breakpointgroup / role / propertytype/h1/line-height

Omission in practice

State is dropped when the token describes the resting case. The element and role stay exactly where they were.

+ Correct
surface/primary surface/primary/hover

Two slots or three - the role is always second.

x Wrong
surface/primary/default surface/hover/primary

Never write default as a state. Never put state before role.

Compound roles use a hyphen, not a slash

surface/primary-subtle, not surface/primary/subtle. The role is one slot - "the subtle variant of primary" is a single meaning, and splitting it would make the third position mean "role" in some tokens and "state" in others.

04

Slot reference

What belongs in each slot.

Element - Interface only

What kind of thing is being coloured. Closed list - never invent a synonym. This is the slot where systems rot fastest.

texticonsurfaceborderring
UseNotCovers
surfacebg, background, fillAny frame or shape fill
textfg, color, content, inkText only
iconfg, glyph, symbolIcon fills. Separate from text because an icon beside muted text is often not the same colour
borderstroke, outline, lineStroke colour
ringfocus, halo, glowFocus indicator drawn outside the border

Changed in v2: bg became surface, fg split into text and icon. The split exists because 1,753 icons had no colour contract at all - one fg could not express "muted icon, full-contrast label".

Role - Interface only

What it means, or how prominent. Two families.

Neutral ladder - prominence within the greys:

defaultsecondarytertiarysubtlemutedstrongstrongerplaceholderdisabledinverseon-colorinteractive

Accent - one of five meanings, optionally with a weight suffix:

primaryerrorsuccesswarninginformation

Suffixes: -strong, -subtle, -tint. Written with a hyphen: border/error-strong.

Every accent role gets the same slots

No role is allowed a bespoke shape. -subtle is always the 200 step, plain is always 500, -strong is always 700 - for every role. This is what stopped border/brand/default being a saturated blue while border/success/default was a pale tint.

State - Interface only

The interaction or condition. Always last. Closed list. The resting state is implicit and is never written.

hoverpressedfocusselectedcheckedindeterminateexpandedinvalidloadingread-onlyvisited

States may compose. Join as <state>-<state>, in the order they appear above - so selected-hover is written hover-selected. One legal spelling per combination.

disabled is a role, not a state - it is terminal and never combines with anything.

Group - Semantics only

primaryneutralsuccesswarningerrorinformationchartbasealpharadiusborder-widthfonticon-size

Colour groups carry a numeric step (50-900). Shape and density groups carry a named step.

Primitives are keyed by value, Semantics by role

A primitive is scale/8, never radius/md; font/weight/400, never font/weight/regular. A primitive carrying a role name collides with the Semantics token of the same name - twelve CSS custom properties once had two tokens claiming them, and the build silently dropped one. scale/* holds the numbers that radius/* and border-width/* give names to.

Two icon scales

icon-size/2xs...xl (12/14/16/20/24/32) sizes every icon, inside a control or not. There were briefly two scales - control/<step>/icon-size held 16/20/24, aliasing the same primitives under a second set of names. It was deleted with the rest of the control group.

The 14 rung was inserted on 2026-08-06 for the small Button. Because a ladder is indexed by value it could not be appended, so the old xs (12) was renamed 2xs and xs became 14 - a breaking change that raises no type error. spacing/14 was added at the same time, since the ladder aliases spacing/*.

05

Closed vocabularies

These lists are the scaling mechanism. Depth is not what kills a design system at 400 tokens - synonym drift is. Adding a word requires an amendment (section 13).

SlotStatusGrows?To add a word
ElementClosedEffectively neverAmendment. Five elements cover every paintable property in Figma.
Role - neutralClosedRarelyAmendment. Must slot into the existing prominence order.
Role - accentClosedOnly with a new meaningAmendment, and it becomes a full ramp in Semantics too.
StateClosedRarelyAmendment. Must be a real interaction state, not a variant.
Semantics groupClosedRarelyAmendment.
StepClosedA ramp may gain a stepAdd to Primitives first, then Semantics.
Words that are gone in v2 - do not reintroduce

bg, fg, brand, danger, info, intent, emphasis, emphasized, bold, body, variant, part. Each was either a synonym of a surviving word or a slot that no longer exists. brand is now primary; danger is error; info is information.

06

The ten rules

Everything above is descriptive. These are prescriptive - they settle the hard cases.

01Components bind Interface. Nothing else.

A component may bind Interface for colour and Breakpoint for responsive geometry. Binding Semantics or Primitives directly is a defect, because it cannot be re-themed.

+ Do
surface/success-subtle
x Don't
success/50color/green/50
02There is no Component collection

A component MAY own colour tokens only if it has 3 or more colour-bearing variants AND 3 or more states that change colour. Cap: 12 tokens. Geometry never qualifies.

Promotion is opt-in and one-way. Crossing the threshold never forces a migration, and a component that has tokens never loses them. The check asks only "do you have colour tokens you haven't earned?"

03Alias exactly one tier up

Interface -> Semantics -> Primitives. Never skip, never sideways, never two tokens in the same collection aliasing each other.

04Never encode the value

Outside Primitives, a name describes meaning, not appearance.

+ Do
surface/primary
x Don't
surface/blue-500text/dark-navy
05Depth budget: four segments

Interface tokens are two or three. Primitives are two or three. Nothing legitimately needs five. Hitting the budget means a role is being used as a slot.

06One state per token, composed in vocabulary order

Compound states hyphenate inside the state slot, in the order the vocabulary lists them. Never split across slashes.

+ Do
surface/selected/hover
x Don't
surface/selected/hover/x
07Disabled is terminal

There is no hover-disabled. Nothing can be hovered, focused or pressed while disabled.

08Every accent role has the same slots

If primary gets a -strong, every accent role gets one. A role with a bespoke slot set is how a scale becomes uncalibrated.

09Singular, always

icon not icons, border not borders. A token names one thing.

10Effects are styles, not variables

Figma variables cannot hold shadows or gradients. Elevation goes in effect styles named Category/Name in Title Case. Bind their colours to variables where possible.

Numbers or words?

Use numbers when the scale might gain steps between existing ones - colour ramps, spacing, font sizes. A 350 can always be inserted. Use words when the set is small and complete - thin/default/thick. Never use light/dark as step names; they break the instant a step is added at either end.

08

Where does my token go?

Work down. The first "yes" is your answer.

The one rule that keeps this system small

Variables scale with the design language, not the component count. A component consumes variables; it does not add them. That is what holds the system at ~380 variables whether you have 26 components or 1,000.

Q1

Is it a raw value with no meaning attached?

Yes -> Primitives. family / step

No -> continue

Q2

Does it change between Desktop, Tablet and Mobile?

Yes -> Breakpoint. Geometry and type only - if it's a colour, the answer is no.

No -> continue

Q3

Would a different brand change this, while light and dark would not?

Yes -> Semantics. group / step - a ramp step, a radius, a density.

No -> continue

Q4

Does it differ between light and dark?

Yes -> Interface. element / role / state

No -> It is almost certainly already in Interface. Search before creating.

Q5

Still convinced the component needs its own token?

3+ variants AND 3+ colour states -> You may promote. Cap 12. (Rule 02)

Otherwise -> Bind Interface. Create nothing.

11

Modes

Two independent mode axes, in two different collections. This is what lets a brand and a theme vary without multiplying tokens.

CollectionModesSet onAdding one costs
SemanticsOne per brandThe file, or a top-level frame114 values. Zero new tokens.
InterfaceLight, DarkA top-level frame104 values. Zero new tokens.
BreakpointDesktop, Tablet, MobileA top-level frame30 values.
PrimitivesValue - one only--
Modes multiply, they don't add

Brand x theme x breakpoint in one collection would mean 18 columns to maintain. Kept in separate collections, Figma resolves the combination for you and each collection stays readable.

Scopes and code syntax

Set both at creation, not later.

ElementFigma scopes
surface/*FRAME_FILL, SHAPE_FILL
text/*TEXT_FILL
icon/*SHAPE_FILL
border/*STROKE_COLOR, SHAPE_FILL (dividers are drawn as filled rectangles)
ring/*STROKE_COLOR
radius/*CORNER_RADIUS
spacing/*GAP, WIDTH_HEIGHT
Primitives, Semantics[] - hidden from every picker
codeSyntax is not authoritative

It is what Dev Mode displays, and it can be wrong - an early export had 11 variables advertising a CSS variable owned by a different token. CSS is generated from the token path, never from codeSyntax. The two agreeing is a checked invariant, not something the pipeline relies on.

13

Lifecycle

Adding, changing or deleting a component - the strict pass

Run pnpm --filter @ionbase-ui/tokens tokens:gate. It must be clean before the component is called done.

#GateWhat it stops
1Every name parsesInvented vocabulary, wrong slot order, depth over four
2Aliases go exactly one tier upInterface reaching past Semantics; components binding primitives
3No unearned component tokensThe forwarding layer coming back
4Every accent role has identical slotsA ramp going uncalibrated
5codeSyntax matches the pathDev Mode advertising the wrong CSS variable
6Figma binds every token, and binds no ghostsA token nothing binds; a deleted variable still driving the design

Deleting is two operations, in this order

  1. Unbind every node.
  2. Then delete the variable.

Deleting alone does not unbind: every node keeps resolving the deleted variable and nothing looks broken. tokens:bindings is the only check that sees it, and a ghost is never grandfathered.

Adding a component should add no tokens

Bind Interface for colour, Breakpoint for type, and spacing/* or a Semantics ladder for geometry. If a new component wants twenty tokens, ask which Interface roles are missing - that is where the real gap is.

Renaming

Non-destructive - Figma preserves every binding. The cost is muscle memory and shipped code. Rename freely while the system is young; batch renames once components are in production.

Deprecating

  1. Create the replacement.
  2. Repoint the old token's value to alias the new one - every existing binding keeps working.
  3. Prefix the old name with _deprecated/ so it sinks to the bottom of the picker.
  4. Unbind, then delete, only once nothing references it.

Amending a closed vocabulary

Adding a word to Element, Role, or State is a system-level change. Answer all three:

  1. Is it genuinely absent? Most proposals are synonyms. fill is surface. active is pressed or selected - pick one.
  2. Will it be used more than twice? A word for one token is an override, not a vocabulary entry.
  3. Does every role get it? If you are adding an accent slot, all five accent roles get it or none do (Rule 08).

If all three pass, add the word here and in the file, in the same change.

14

Validator

Type a name. Checks structure, vocabulary, casing and depth - grammar only.

Still unchecked - the honest list

Nothing verifies that an Interface token picks a sensible step for its role, or that light and dark have adequate contrast. Both need a human or a contrast checker, not a grammar parser.

16

Glossary

TermMeans
AliasA variable whose value is another variable. The whole system is aliases.
BindingA Figma node property pointing at a variable. Bindings survive renames; they do not survive being ignored when you delete.
GhostA binding to a deleted variable. Still resolves, invisible to every export.
ModeA column in a collection. Brand in Semantics, theme in Interface, screen size in Breakpoint.
ElementFirst slot of an Interface token: text, icon, surface, border, ring.
RoleSecond slot: what it means or how prominent.
StateThird slot: interaction or condition. Resting state is never written.
StepA numbered position on a ramp, 50 to 950.
PromotionGranting a component its own colour tokens. Opt-in, one-way, capped at 12.
LadderA scale indexed by value - radius, icon-size, border-width, the colour ramps. A component picks a rung. Semantics holds ladders only; a group indexed by usage instead ("a medium control's padding") is a recipe, and recipes need a new entry per usage pattern.
Structural ladderThe surface layering order: page, sunken, default, subtle, muted, raised, overlay.
